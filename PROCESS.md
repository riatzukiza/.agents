## The one domain rule

**Never silently turn similarity into identity.** Two things that look alike
(a recurring failure and an old failure, a new skill and an existing skill,
a spore and a promoted skill) are not the same thing until evidence says so.
In this repository that rule becomes:

- search for overlap before creating a skill,
- keep provenance for imported and promoted skills,
- promote a spore only after review, never in the session that created it.

## The miniature loop

1. Observe — read the repo, the receipts, the relevant skills.
2. Model — name what is actually happening, not what the habit expects.
3. Change — the smallest compatible edit.
4. Verify — with capabilities the harness actually has; record skipped checks.
5. Record — append receipts (`.ημ/receipts.edn`) and a mycology entry.

Evidence flows one way: observations may become facts only with receipts
behind them. The ledger is append-only; the river only flows.
