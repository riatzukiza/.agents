## Problem

A global skill corpus can exist without being reliably understood as an operating system. Different harnesses may discover different paths, skip mandatory substrate skills, confuse connector access with a local checkout, or fail to leave durable learning records.

## Pattern

Any portable skill repository needs a small root governance layer that defines canonical source, instruction precedence, targeted discovery, evidence persistence, harness boundaries, and the delayed promotion path from observed friction to production skill.

## Candidate skill outline

- Name suggestion: `skill-repository-governance`
- Trigger phrases:
  - "make this a skill repository"
  - "canonical agent skills"
  - "global skills repo"
  - "share skills across harnesses"
- Key steps or rules:
  - establish a canonical root contract and repository `AGENTS.md`
  - distinguish global principles, repository instructions, and selected skill procedures
  - discover the smallest relevant skill set rather than loading the full corpus
  - require Receipt River for substantive mutations
  - run Session Mycology after substantive work
  - preserve provenance and defer spore promotion to a later review session
  - state actual harness capabilities and persistence boundaries
- Anti-patterns to avoid:
  - treating the repository as an unstructured prompt dump
  - copying skill trees into harnesses and allowing them to drift independently
  - promoting a new skill in the same session that noticed the pattern
  - claiming local scripts or filesystem checks ran through a connector

## Better path

When adopting or repairing a skill repository, inspect existing substrate skills first, add the smallest root governance contract needed to make discovery deterministic, record the change through Receipt River, and leave any generalized maintenance workflow as an incubating spore for later review.
