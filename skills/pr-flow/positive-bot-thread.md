# Independently assessed Bot-thread preservation

SPDX-License-Identifier: GPL-3.0-or-later

The separate preservation purpose acknowledges an affirmative Bot request to
retain verified existing behavior. Keep every original finding ID, body,
priority, enclosing review and native history. P1 in a refutation title remains
P1. Generic Handled, rejection, opener withdrawal, CodeRabbit LGTM body and
author-only informational judgments keep their existing meanings.

The reviewed source profile is exact native `open-hax/knoxx` name/database/node
identity and the observed GitHub Actions root publisher tuple. That publisher
gains no approval, assessor, withdrawal or rejection role. Independently
configured OpenCode/MiMo tuples belong to this separate purpose; their presence
alone is not judgment or operational admission. No title, ID exemption, model
label or semantic regex qualifies an affirmative root.

Protected source review, hosted qualification and separate adoption are required
before use. This rule cannot bootstrap its own PR approval/merge/installation.
Synthetic local fixture publications are never native evidence. All other
findings, body items, required checks, available providers, coverage, review
cohorts, round minimums, approval quorum and protection remain obligations.

## One explicit native scope and full corpus

V2 declares one sorted unique vector of exact [thread-id root-comment-id] pairs
under one native repository/PR/current full head. Every member must exist once,
with complete native Bot root identity and ordered conversation/review custody.
One authorized User proposal and one distinct independent native assessment
cover EVERY member, with a separate preservation judgment/reason/evidence row
for each. Missing, duplicate, reordered, extra, implicit, negative, uncertain or
mixed rows deny the whole scope. Unrelated actual negative findings remain.

This shared scope fixes the V1 design's mutual revocation: separately appending
two proposal/assessment pairs to one global issue history could never admit
both roots simultaneously. V2 still permits no arbitrary issue interleaving.
The actual proposal and actual assessment are exactly the two issue records
extending one immutable complete prefix; later issue changes refuse/revoke.

Use the existing `native-context/collect-context` with the separately reviewed
preservation profile and canonical injected native/permission/history readers.
Bot fragments collect numeric/node/type identity without granting writer roles.
`native-context/hydrate-preservation-context` accepts explicit relevant source
paths and target pairs before the proposal. It reads immutable current-head Git
blobs, verifies exact native repo identity, complete UTF-8 byte size,
nontruncation, Git-blob SHA-1 and SHA-256, and retains actual source text. Candidate
code never executes; unavailable, binary or truncated sources are refused.

One versioned ordered-vector carrier binds repo/PR/state/draft/head, every
ordered native thread, root/replies, resolution/outdated flags, paths/lines,
actor identities, current/original commit, exact body/diff hashes, complete
enclosing-review body/state/identity/commit/edit metadata and the ordered issue
prefix's IDs/nodes/URLs/actors/body hashes/times. Actual source/test text and
complete decoded admission/revocation history must reach the assessor. Missing
history is never valid empty history. Hashes are reader-acquired facts, not
proposal claims or caller eligibility flags.

## Prospective and actual independent judgment

`positive-thread/proposal-body` returns only exact prospective text over fresh
complete corpus/source custody and all pending members. The host must
independently authenticate/publish/recollect a real authorized native User.

```text
Preservation proposal v2 for <full current head>:
["positive-bot-cohort/v2" <repo-node> <pr-node> [[<thread> <root-number>] ...] <conversation-sha256> <issue-prefix-count> <issue-prefix-sha256> [[<path> <head> <blob-sha1> <source-sha256>] ...] <reason> <evidence>]
```

`positive-thread/assessment-publication` checks one accepted full-input summary
and returns exact body/proposal/principal bindings plus a future creation-after
condition. It invents no native ID, time, URL, observation, qualified disposition
or settlement. Real publication/readback must pass recomputed actual proof.

```text
Preservation assessment v2 for <full current head>:
[<the proposal's first eight fields> <proposal-native-id> <proposal-body-sha256> [[<thread> <root-number> "preservation" "complete-context/existing-behavior-preserved/no-unaddressed-defect/no-corrective-request/no-unresolved-question" <reason> <evidence>] ...]]
```

The assessor must evaluate the entire native corpus, each exact root/review,
relevant immutable source/test text, issue history and reasoning. Preserve each
affirmative request explicitly; independently find no unaddressed defect,
corrective request or unresolved question. Informational no-request and
rejection-agreement judgments cannot be copied here. Mixed, uncertain,
incomplete or finding judgments fail closed.

Authenticate the configured native assessor tuple and accepted invocation,
physically distinct from every publisher/App, proposer, PR author and final
writer. A second model label on the same App cannot self-corroborate. Native
identity/protocol syntax alone cannot prove actual full-input delivery, runtime
independence or semantic truth; these remain reviewed transport/source
obligations. Do not publish a synthetic transcript to fill that gap.

The existing eta-mu native hosts currently expose informational actionability
and rejection purposes. This policy source supplies no reviewed operational
cohort-assessor adapter. After protected adoption, reuse their accepted
full-input/identity/native-publication boundary with a separately reviewed
purpose/profile dispatch to this pure prospective API; preserve dependency,
invocation, source/input/result and real App readback custody. That later runtime
work belongs in its owning repository, not this canonical policy proposal.

## All-member custody and one-thread native effects

The reader can reconstruct a candidate base by removing a terminal reserved
preservation-writer candidate only from declared members and resetting those
members' resolution flags. This is not admission: pure proof validates EVERY
candidate before any normalized carrier qualifies. A malformed/unauthorized,
wrong-root/head/source, edited or mixed other-member append denies all members.
Resolved:true without its verified writer is invalid and emits no qualified
observation. Every nonmember thread and every prior tuple remains unchanged.

Record complete sorted per-member phases in the existing append-only canonical
history: pair, actual writer manifest (or nil), actual resolution boolean. Only
pending→one verified writer append→resolved advancement is permitted. Known
writer manifests cannot change/disappear; resolved members cannot reopen.
Changed target sets/context, unknown additions, deletion/edits/reopening and
restoration revoke the shared assessment ID. Restoring old text cannot revive
known revoked evidence. Reassessment needs a fresh proposal/source.

A later authenticated authorized native User uses existing `settle`, one target
at a time, with exactly this five-line body:

```text
Handled: preservation v2 for <full current head>:
Finding: <native thread> comment<native root number>
Assessment: <actual shared assessment issue-comment URL>
Reason: <verified existing behavior and substantive preservation rationale>
Evidence: <scoped source/test/document evidence>
```

Reserved-family detection precedes generic writes, including truncated,
case/spacing, missing-colon, tab/newline or bold forms; malformed family bodies
refuse rather than falling through. Unrelated ordinary Handled remains subject
to existing law. The specialized path uses one fixed GitHub.com token-stripped
keyring environment, no credential fallback/retry, fresh full User/write-role
readback and complete corpus/source/history comparison before one reply attempt.

Verify the actual native reply's ID/node/URL/body/actor and later unedited
chronology. Its actual writer-owned empty COMMENTED review binds current head;
historical originalCommit remains historical and review creation need not equal
reply creation. This is an explicit narrow admission condition, not a claim
all GitHub replies have this shape. Unsupported shapes remain uncertain.

After verifying exactly the target's actual append/count increment, recheck ALL
members and full history/actor/permission before one resolution attempt. Final
fresh readback must differ only by that target's resolution flag. Known verified
member1 phases can advance while member2 is settled, leaving both qualified in
one final snapshot. A member's own writer and resolution are necessary for its
settlement; pending members still block merging. Unknown/partial outcomes retain
actual attempts/readbacks, exit3 and never retry automatically.

The pure blocker law recomputes proof; supplied preservation/settled flags
cannot clear P1. Purpose-isolated records share the existing complete history
codec/ledger without relabeling informational records. Only uncontested actual
resolved Handled proofs clear their own severity blockers. No approval,
coverage, reviewer cohort, full-PR review, completed round, CI, deployment,
installation or protected-adoption credit is created.
