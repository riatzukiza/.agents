# Legacy runner qualification

This document qualifies only the explicitly selected legacy runner. The current SKILL.md describes native execution; canonical/upstream-skill.md preserves the original SKILL.md bytes. The five other original upstream assets are unchanged and covered by tests/source-integrity.js. The generated agents/openai.yaml and assets/icon.svg are reconciliation metadata, not upstream source. This qualification file is an independently added sidecar, not an upstream contract or a modification of the runner. Native roles and evidence follow references/INSTRUCTIONS.md and references/native-schema.md instead.

The upstream runtime requires Babashka (`bb`), OpenCode, and the three agent definitions registered in OpenCode. The commands in upstream SKILL.md assume a different installation location; substitute the actual skill directory. Neither runtime was available during packaging, so execution and registered agents have not been verified.

Active user instructions, applicable repository rules, and platform permissions take precedence over project-specific statements in upstream agents. In particular, the bundled implementer's Clojure-specific constraints are not universal: the user's preference for functional promises remains controlling where applicable. Reviewers and skeptics must have independently enforced read-only access; implementers must have independently enforced declared write boundaries.

Before using this runner as a gate, implement external fail-closed checks for complete expected job and vote counts, valid JSON against declared schema, successful agent termination, exact current revision and inputs, isolated packet boundaries, and actual gate results. Inspection of the pinned source indicates agent failure can coexist with a passed implement stage if gates are green; failed review jobs can disappear from vote input; schema is included in the prompt but not mechanically validated; journal keys omit important identity inputs including prompts, schema and current revision. A finding without enough valid votes is not evidence of a clean review. Use an immutable new workflow ID for every head, prompt, schema, or attempt; independently bind and verify those inputs. Never use --fresh on retained runs because it deletes the journal. Do not rely on :stage/uuid or :stage/commit to promote or commit automatically. Reconcile all outcomes and require explicit decision after successful qualification. The smoke --limit truncates votes and cannot establish quorum.

No upstream CONTRACT.edn was present at the pinned source. This qualification is a packaging contract; it does not claim to be upstream.
