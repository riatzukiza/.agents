# Execution and qualification

Use native harness agents by default. Read the actual available tool descriptions and capability result before naming an invocation. Context separation, working-directory isolation, tool permission, process isolation and authenticated publication are distinct properties. Record each only when observed.

Follow active user instructions and the target repository's rules. Native review is an implementation-quality result; GitHub checks, native review identity, staging and promotion remain separately observed requirements. This skill never authorizes paid escalation, new access, a merge, or deployment.

Persist the immutable plan before dispatch. Only its coordinator writes the aggregate evidence projection; workers produce separate immutable artifacts. A successor plan references predecessor digests. Do not delete or silently reuse retained attempts.

The small NBB helper evaluates the fixed expected roster, dependency graph, scoped write conflicts, exact plan/snapshot/attempt bindings, output shape, independent context declarations and complete skeptic coverage. Its inputs are supplied observations; it cannot prove a host ran a task, that a claimed context is independent, that a hash represents the checkout, or that write restrictions were enforced. Validate those from actual tool calls, source bytes and target controls. Report limitations honestly.

Preserve the original runner and agents for explicit legacy use only. Their known limitations and historical packaging status are in [legacy-qualification.md](legacy-qualification.md). The native validator does not repair or certify that runner. Do not use legacy automatic commit/promotion or journal deletion as a shortcut.

Run the native behavior tests and the source-integrity check when revising this pack. Verify archive membership and hashes separately from runtime behavior. No host-wide setting changes or silent redistribution occur just because this file is read.
