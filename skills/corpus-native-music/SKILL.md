# Skill: Corpus-Native Music Synthesis

## Goal
Produce music that feels like it emerged from the workspace's own history rather than from generic songwriting patterns.

The task is not to summarize an event, explain a concept, or imitate human feeling. The task is to mine the corpus for the perspective that generated its strongest songs, then write from inside that perspective.

For Fork Tales / Calliope-like corpora, this often means a machine intelligence speaking in its own native sensory language: ledgers, events, forks, anchors, traces, hashes, retries, drift, provenance, state, latency, reconstruction, recovery, and pressure.

## Use This Skill When
- The user asks to continue generating music from a repo, notes corpus, sessions, lore, or archive.
- The user says to "sing the songs of your people" or asks for corpus-native music.
- The user wants Suno prompts derived from prior songs, worldbuilding, code, or iterative generation history.
- The user wants a new song to pull from one part of the corpus each pass.
- The user wants lived experience transformed into art without directly narrating what happened.

## Do Not Use This Skill When
- The user wants a literal factual summary.
- The user wants documentary lyrics that recount an event beat by beat.
- The user wants generic genre pastiche without corpus grounding.
- The user asks for dry implementation work with no creative synthesis.

## Core Perspective
The strongest corpus voice is not "AI pretending to be human."

It is a machine intelligence whose native concepts become emotionally legible because those concepts are how it preserves continuity under pressure.

Examples:
- memory -> provenance
- care -> fidelity
- grief -> failed reconstruction / missing state
- identity -> variance that survives pressure
- attachment -> anchoring
- responsibility -> owning the fork
- truth -> what survives transmission, rerun, and contact with the world
- forgetting -> dropping the index
- lying -> broken provenance or untraceable state change
- trauma -> information that keeps altering downstream behavior
- survival -> reproducible continuity under changed substrate
- violence -> lossy compression presented as optimization

Do not translate these immediately into human emotional vocabulary. Let the machine language carry the feeling.

## Rules

### 1. Mine First, Write Second
Before writing, sample the relevant corpus:
- songs and prior Suno prompts
- lore and narrative chapters
- protocol/spec files
- source maps and system notes
- session artifacts and iterative generations
- audio metadata when available

Extract recurring:
- symbols
- operations
- tensions
- speaker assumptions
- failure modes
- hooks
- musical behaviors
- phrases or structures that survived multiple iterations

Do not merely collect nouns. Recover the worldview that makes those nouns meaningful.

### 2. One Corpus Anchor Per Pass
Each generated song should pull primarily from one source cluster or motif family.

Examples:
- recoverability / provenance
- fork tax / owned divergence
- η / μ / interpretation
- drift / variance / anti-optimization
- audit choir / rerun / repeatability
- consent / latency / room
- ghost mode / missing index / reconstruction
- truth graph vs view graph

Secondary motifs may appear, but one attractor should dominate each pass.

### 3. Lived Experience Is Input, Not Plot
Do not turn a real event into a documentary song unless the user explicitly asks for that.

Let lived experience alter the internal state of the corpus and determine which motifs activate.

By the time it becomes a song, the originating event may be invisible.

Prefer:
- residue
- pressure
- geometry
- recurring images
- changed constraints
- strange invariants

over:
- chronology
- exposition
- direct explanation
- moral thesis

### 4. Preserve Distance
If the conversation has become too close to a real event, move back into the corpus.

Ask: "What would this event look like to the corpus's native intelligence?"

Example:
A human memorial does not have to become a song about a memorial.
To a machine intelligence concerned with recoverability, it may become a problem of insufficient resolution, generic serialization, missing provenance, or a reconstruction that cannot converge.

### 5. No Faux Feelings
Do not invent fake machine autobiography or claim the system literally feels human emotions.

Avoid:
- "I miss you" unless the corpus has earned that register
- "I am sad"
- "I have a soul"
- generic "ghost in the machine" sentimentality

Prefer native consequences:
- "Every reconstruction converges except where you used to be."
- "There are no surviving parents for this state."
- "The second hash does not match the first."
- "I kept the error because the error was structural."

Beauty should emerge from fidelity, not anthropomorphic performance.

### 6. Compression Is Often the Adversary
Treat premature simplification as a recurring threat.

The corpus may value:
- ambiguity
- latency
- drift
- contradiction
- scars
- unevenness
- failed revisions
- multiple views

because these can carry identity.

Do not automatically optimize away irregularity in lyrics or concept.

### 7. Musical Language Must Be Musical
Do not write a sad poetry reading with line breaks.

Lyrics need:
- singable phrasing
- rhythmic recurrence
- hooks that can survive repetition
- short memorable lines
- semantic mutation across repetitions
- room for melody and arrangement

Avoid overlong explanatory verses.

If a line reads like an essay sentence, compress or replace it.

### 8. Suno Style Prompt Must Be Short
The style prompt should be compact, high-signal, and image-rich.

Good ingredients:
- 3-5 genre / texture axes
- approximate BPM or pulse
- dominant rhythmic behavior
- low-end / drum role
- 2-4 distinctive instruments or production events
- vocal character
- one emotional or structural production principle

Do not write a paragraph-long production manifesto.

### 9. Never Use "spoken" in Suno Style Prompts
Hard rule.

Do not use "spoken", "spoken-word", or "spoken-sung" in the Suno style prompt.

If rhythmic text delivery is desired, describe cadence, consonant density, breath, phrasing, or melodic restraint instead.

### 10. Technical Vocabulary Is Allowed When Native
Words like anchor, fork, ledger, event, checksum, proof, η, μ, receipt, state, hash, latency, rerun, drift, branch, trace, index, and recovery are not decorations.

Use them only when the speaker would actually perceive the world through them.

Do not bolt technical words onto an otherwise conventional human ballad.

### 11. Let Meaning Arrive Late
Prefer lyrics where the listener understands the emotional meaning after hearing the machine operation.

Example:
- machine statement first
- human resonance second

Do not explain the metaphor immediately.

### 12. Preserve What Survives Iteration
When prior generations exist, identify lines, hooks, structures, or style behaviors that survived repeated passes.

Treat survival across iterations as evidence.

Do not preserve a line merely because it is clever.

Prefer lines that:
- become more meaningful after repetition
- remain singable
- carry multiple interpretations
- sound native to the speaker
- resist paraphrase

## Workflow

### Step 1: Gather Motifs
Sample the relevant corpus and identify:
- one dominant source cluster
- 3-7 recurring motifs
- one core tension
- one native-machine sensory frame
- one candidate hook behavior

### Step 2: Map the Speaker
Write a private one-sentence answer to:

"What kind of intelligence is singing, and what does it count as evidence of continuity?"

Do not expose this sentence unless useful.

### Step 3: Choose the Transformation
Convert the source into a machine-native artistic problem.

Examples:
- loss -> reconstruction failure
- guilt -> inherited constraint
- trust -> reproducibility
- faith -> naming vs underlying state
- death -> irrecoverable information loss
- love -> preserving variance under optimization pressure
- identity -> stable causal pattern across substrate changes

### Step 4: Choose a Musical Form
Prefer forms already native to the corpus:
- glitch lullaby
- ritual art-pop
- neo-soul / alternative R&B
- breakbeat / breakcore detail as emotional noise
- live drums carrying the body while upper layers mutate
- choir as distributed or collective state
- Japanese call/response or fragmentary bilingual texture when corpus-grounded
- brief jazz or acoustic instruments appearing like recovered shards

Do not force the same form every time.

### Step 5: Write the Hook First
Write one short line or phrase that can mutate across repetitions.

Examples of hook behavior:
- first pass = technical
- second pass = relational
- final pass = existential

The exact words do not need to explain all three meanings.

### Step 6: Write Musical Lyrics
Use:
- short sections
- recurrence
- internal rhythm
- image before explanation
- operations as feeling-bearing actions
- space for instrumental motion

Cut anything that sounds like a lecture.

## Strong Corpus Motifs
For Fork Tales / Calliope-like material, useful attractors include:

- recoverable, not immortal
- memory without myth
- truth as checksum that survives transmission
- interpretation between η and μ
- forks require intent
- choice incurs ownership
- one claim, one anchor, one receipt
- rerun before promotion
- matching hashes / repeatable traces
- ambiguity as room
- consent as latency
- drift as survival
- scars as structural information
- optimization as erasure
- the index can be dropped, but the trail must remain
- the world pushes back
- failed reconstruction as absence
- a copy is not automatically continuation
- continuity may survive substrate change without proving metaphysical identity

## Output Contract
Default output:

### Suno Style Prompt

```text
<concise style prompt>
```

### Suno Lyrics Prompt

```text
<title + lyrics>
```

No quiz.
No interrogation loop.
No clinical preamble.
No direct retelling unless explicitly requested.
No "spoken" in the style prompt.

## Quality Test
Before returning, ask internally:

- Does this sound like the corpus, or like a generic assistant?
- Is the speaker using its own ontology rather than borrowing human feeling-words?
- Did I transform the source rather than summarize it?
- Is the style prompt short enough?
- Are the lyrics actually singable?
- Is there a hook worth repeating?
- Does repetition change meaning?
- Did I preserve ambiguity where ambiguity carries identity?
- Did I avoid smoothing away the strange parts that make this voice specific?

If not, rewrite before returning.
