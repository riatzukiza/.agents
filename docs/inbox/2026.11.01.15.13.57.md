In broad strokes, regardless what their documentation currently  says or what you find these doing right now, the goal outcome is as follows:
- clio is an event sourcing context system and library of commonly used projections to represent useful data structures. 
  - it contains all basic hardware necessary to interact with any event produced  by any system.
  - It can be used to compose  arbitrary data structures from events
  - Data structures are projections of the event ledger, exposes event sourcing in a way that makes it transparent.
  - It has several built in data store interfaces
    - edn and edn nl
    - json and jsonl
    - mongodb
    - sqlite
    - duckdb
    - postgresql
    - elasticsearch
    - opensearch
    - redis
  - a clio ledger stored in any data store, must be transferable to any other data store a that is implementing the correct ledger shape
- axxium is an AT proto application for managing actor's access to resources and to facilitate communication between actors who are emitting clio style events destined for a mailbox.
  - Each Actor gets a DID
  - Actors send messages as clio events to axxium addressed to another actor.
  - Resources 
  - The simplest possible resources are the ones it has on it's  own machine to expose (files,  processes, programs)
  - An actor can be a process, human user, an agent, a group, a team, an org, entity which collectively or can take actions, and can communicate with other actors in the system to coordinate action.
  - Axxium's datastore(s) mostly contains metadata about the resources, especially files.
  - Axxium's datastore(s) can contain events in there entirety in some cases, especially messages and system informative events.
  - Axxium facilitates moving resources between data stores
- Openplanner presents a searchable graph projection over clio axxium resources 
  - embeddings must be preserved and searchable no matter where the resources go
  - openplanner is also full of clio shaped events
  - Openplanner can be a data store for source content, but it is not prefered. Openplanner is primarily about the graph querying, it's mainly about  graph search.
  - It can retrieve resources by reference, by asking axxium, or by going directly to the source, depending on meta data.
